# Vault 2FA Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** VS Code extension with the Chrome Authenticator's features, an encrypted vault and a modern webview UI.

**Architecture:** Pure core modules in `src/core` (no `vscode` import, unit-tested with vitest); a host layer in `src/host` wires them to VS Code (view provider, commands, status bar, timers); the webview (`webview/`) only renders state messages and sends intents.

**Tech Stack:** TypeScript 5, esbuild, vitest, hash-wasm (Argon2id), node:crypto (AES-GCM, HMAC), jsQR (webview), crypto-js (Chrome backup import only).

**Spec:** `docs/superpowers/specs/2026-11-25-vault-2fa-design.md`

## Global Constraints
- VS Code engine `^1.85.0`; Node 18+ APIs only.
- No telemetry; the only network call is the manual clock sync to `https://www.google.com`.
- Decrypted secrets never leave the extension host, except the codes shown in the webview.
- Vault envelope `{v:1, kdf:{alg:"argon2id", salt, m:65536, t:3, p:1}, iv, ct}`, base64 fields.
- Defaults: autoLockMinutes 15, clipboardClearSeconds 30, backupKeep 10.

## Review Focus
- Wrong password → clear error, vault file untouched (test in Task 2).
- Secrets with spaces or lowercase letters, or missing `=` padding → codes still correct (Task 1).
- `otpauth://` with URL-encoded issuer/label and the issuer in both label and query → parsed once (Task 3).
- Crash mid-write → previous vault intact (atomic write, Task 2).
- Import of duplicates (same secret+account) → skipped, counted (Task 3).

### Task 1: OTP core — `src/core/otp.ts`, `src/core/base32.ts`
- Produces: `generateCode(e: Entry, now: number, offsetSec: number): string`, `remainingSeconds(period, now, offset)`, `base32Decode(s): Buffer`, `base32Encode(b): string`, and the types `Entry {id, type:'totp'|'hotp'|'battle'|'steam'|'hex'|'hhex', issuer, account, secret, period, digits, algorithm:'SHA1'|'SHA256'|'SHA512', counter, pinned, color?}`.
- [ ] Tests: RFC 6238 vectors (SHA1/256/512 at T=59 → 94287082 / 46119246 / 90693936, 8 digits); RFC 4226 HOTP counter 0..2 → 755224, 287082, 359152; Steam output of 5 chars from `23456789BCDFGHJKMNPQRTVWXY`; battle → 8 digits; secret `"jbsw y3dp ehpk 3pxp"` works.
- [ ] Implement with node:crypto `createHmac`, then commit.

### Task 2: Vault — `src/core/vault.ts`, `src/core/envelope.ts`
- Produces: `seal(obj, password): Promise<Envelope>`, `open(env, password): Promise<unknown>` (throws `WrongPasswordError`), `deriveKey(password, kdf)`, `sealWithKey`/`openWithKey`; `class VaultStore(filePath)` with `exists()`, `create(pw)`, `unlock(pw)`, `unlockWithKey(key)`, `lock()`, `isUnlocked`, `entries`, `add/update/remove/reorder/pin`, `changePassword(old,new)`, `exportKey()`, `save()` (atomic write).
- [ ] Tests: round trip; wrong password throws and leaves the file bytes unchanged; tampered ct throws; lock clears entries; changePassword re-encrypts the vault.
- [ ] Commit.

### Task 3: Parsers and importers — `src/core/uri.ts`, `src/core/migration.ts`, `src/core/importers.ts`
- Produces: `parseOtpauth(uri): Partial<Entry>`, `toOtpauth(e): string`, `parseMigration(uri): Partial<Entry>[]` (real protobuf varint decoding), `importAny(text, password?): {entries, failed}` that detects otpauth lines, Chrome backup JSON (plain / `key.enc` / legacy password-encrypted), andOTP array, 2FAS `services`, and `.vault2fa` envelope; `dedupe(existing, incoming)`.
- [ ] Tests for each format, plus a migration URI built from a known protobuf, plus the Review Focus cases.

### Task 4: Backup, advisor, time sync — `src/core/backup.ts`, `src/core/advisor.ts`, `src/core/timesync.ts`
